# docshot

Capture the screens, build the manual.

Two steps, one configuration file:

1. **capture** — Playwright walks the running application and saves one PNG per screen, driven by a JSON list of routes and interactions instead of a screenshot script written per system.
2. **build** — a Markdown source per module becomes a `.docx` inside *your* corporate template: its styles, header, footer, numbering and document variables are preserved, only the body is replaced.

No Word, no LibreOffice, no Python package to install — the generator uses the standard library alone. The only dependency is Playwright, and only for the capture half.

## Why

Validation manuals go stale the moment the interface changes, and rewriting them by hand means the screenshots and the text drift apart. Here the screenshots are regenerated by a command, the prose lives in Markdown next to them, and the document that reaches the reviewers still looks like the company's own template.

## Install

```bash
git clone <this repo> ~/dev/docshot
cd ~/dev/docshot
npm install                    # Playwright, for the capture half
export PATH="$HOME/dev/docshot/bin:$PATH"
```

Python 3.8+ and Node 18+ are enough. `docshot build` on its own needs neither `npm install` nor a browser.

## Quick start

```bash
mkdir my-manual && cd my-manual
docshot init                   # docshot.config.json + source/ + shots/ + template/
cp ~/Downloads/corporate.docx template/base.docx
docshot inspect                # what the generator found in that template
docshot probe /customers       # what that screen offers, as steps to paste
docshot check                  # validate the config and the sources, no browser
docshot capture                # shots/*.png
docshot build --single         # build/manual.docx
```

`docshot all` runs capture and build in sequence.

## Writing the config without guessing

`docshot probe <route>` logs in, opens the route and prints every button, tab
and field it finds, each with the JSON step that addresses it:

```
buttons (37, 28 in the app chrome — --all shows them)
  New customer                     {"click":{"role":"button","name":"^New customer$"}}
  (no accessible name)  menu trigger  {"menu":{"selector":"button[aria-haspopup=\"menu\"]"}}
```

`--after '<step json>'` probes what appears *after* an interaction, which is how
you list the fields inside a dialog before writing the section that describes
them.

`docshot check` runs before any browser starts and catches what silently ruins a
batch: an unknown key, an invalid regex, a `waitForUrl` loose enough to match
the login page itself, two shots with the same name, an image a manual
references that no shot produces, a screenshot nobody uses, a literal password
where a `${VAR}` belongs.

During the run, a shot whose interaction leaves the screen unchanged is
reported — that is the click that missed its target and photographed the page
behind it.

## Configuration

Everything lives in `docshot.config.json`, found by walking up from the working directory. `${VAR}` anywhere in the `capture` block is replaced by an environment variable — from the shell, or from a `.env` beside the config, which is gitignored.

```jsonc
{
  "template": "template/base.docx",   // any .docx; a plain one is used if missing
  "sourceDir": "source",              // Markdown, one file per module
  "shotsDir": "shots",                // where captures land and where images are read from
  "outDir": "build",
  "lang": "pt-BR",
  "cover": true,                      // title page
  "revisionHistory": true,            // closing control tables
  "approval": true,
  "document": { "titulo": "...", "versao": "1.0.0", "elaborador": "..." },
  "labels": { "approval": "APPROVAL" },     // rename any generated heading or column
  "consolidated": {
    "output": "manual.docx",
    "appendIncludes": ["technical"],        // shared block, emitted once at the end
    "rewrites": [["This manual", "This chapter"]]
  },
  "capture": { "...": "see below" }
}
```

### capture

```jsonc
{
  "baseUrl": "http://localhost:3000",
  "viewport": { "width": 1440, "height": 900 },
  "deviceScaleFactor": 2,              // retina-sharp images inside Word
  "settleMs": 3000,                    // network idle, then this pause
  "colorScheme": "light",
  "mask": [".customer-name", "[data-pii]"],   // painted over in every screenshot
  "auth": {
    "url": "/login",
    "fields": { "#email": "${APP_USER}", "#password": "${APP_PASSWORD}" },
    "submit": { "role": "button", "name": "sign in" },
    "waitForUrl": "/(?!login)"
  },
  "shots": [
    { "name": "studies-01-list", "goto": "/studies" },
    {
      "name": "studies-02-form",
      "goto": "/studies",
      "steps": [{ "click": { "role": "button", "name": "new study" } }]
    }
  ]
}
```

A target is `{ "selector": "..." }`, `{ "role": "button", "name": "regex" }`, `{ "text": "..." }` or `{ "label": "..." }`; `name` is a case-insensitive regular expression, and `nth` picks among several matches.

Steps run in the order they are listed:

| Step | Does |
| --- | --- |
| `goto` | navigate, then settle |
| `click` | click a target; a target that matches nothing is a warning, not a crash |
| `menu` | focus + Enter — icon-only Radix/Headless menu triggers swallow `click()` |
| `fill` | `{ "selector": "...", "value": "..." }` |
| `press` | a key, e.g. `"Escape"` |
| `hover`, `scrollTo` | on a target |
| `wait` | milliseconds |
| `waitForText` | wait for text to appear |
| `repeatUntilGone` | `{ "text": "...", "click": target, "max": 12 }` — page forward past an empty state |
| `screenshot` | an extra capture mid-sequence, by name |
| `evaluate` | a JavaScript expression, for anything left |

Useful flags: `--only name,name`, `--headed`, `--list`, `--config path`.

### Markdown dialect

`#`…`######` headings · `- item` and `  - subitem` · tables with `| a | b |` · `**bold**`, `*italic*`, `` `code` `` · fenced code blocks · `![caption](shot.png)` read from `shotsDir` · `---` alone on a line for a page break · `{{include: name}}` splicing `source/_name.md`.

Front matter (`titulo`, `subtitulo`, `versao`, `data`, `elaborador`, `cargo_elaborador`, `departamento`) fills the cover and the control tables, overriding `document` from the config.

## The template

`docshot inspect` reports what was found:

```
headings:   1=Ttulo1, 2=Ttulo2, 3=Ttulo3, ...
bullets:    Listadeitens (numId 2)
table cell: Tabelacontedo
sectPr:     reused from template
text width: 6.69 in
```

Heading styles are matched by their Word name (`heading 1`, `Título 1`, …), so a template in any language works. The bullet list is the one the template's own bullet style points at. The section properties are copied verbatim, which is what keeps the header and footer — and with them the document code, revision and validity fields — attached to every generated page. Anything missing degrades to direct formatting instead of failing.

Screenshots are scaled to the template's usable text width and never cropped. `"maxImageWidthIn": 6.5` pins them to a narrower column when the document should keep an existing layout.

## For coding agents

`AGENTS.md` at the root is the working contract — the loop, the dialect, the
configuration reference, and the traps that each cost a review cycle. `CLAUDE.md`
points at it, and `.claude/skills/write-manual/` carries the procedure for
turning a running system into a manual. Point whatever assistant you use at
`AGENTS.md` before it writes configuration or prose.

## Layout

```
AGENTS.md            the contract for coding agents (CLAUDE.md points here)
bin/docshot          dispatcher
capture/capture.mjs  the Playwright runner
capture/probe.mjs    reports what a screen offers
capture/shared.mjs   config, login and target resolution
docshot/             the .docx generator (standard library only)
  template.py          reads styles, numbering and sectPr out of the template
  markdown.py          the source dialect
  ooxml.py             paragraph, list, table and image builders
  doc.py               cover page and control tables
  package.py           clones the template package, swaps the body
  lint.py              the static checks behind `docshot check`
examples/demo-app/   a project layout to copy, binaries left out
```

## Notes from the field

- Capture against a seeded demo environment, never production — and put every field that can carry personal data in `mask`.
- Take one screenshot and look at it before running the whole batch: a click that silently missed its target photographs the screen behind it, and nobody notices until the document is in review.
- Keep `shots/` in version control next to the sources. That is what makes a document reproducible months later.
